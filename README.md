افزونه شمسی ساز پارسی‌دیت یکی از ابزارهای کاربردی و مفید برای کاربران وردپرس فارسی است که امکان شمسی کردن تاریخ وردپرس
را برای کاربرانش فراهم می‌کند. این افزونه در سال ۱۳۹۲ توسط تیم توسعه وردپرس پارسی ایجاد شد و با هدف ساده‌سازی فرآیند
نمایش تاریخ‌ها در وب‌سایت‌های فارسی زبان به کار می‌رود. این افزونه در طی سال‌ها مورد استفاده محبوب‌ترین سایت‌های وردپرسی
فارسی زبان بوده و افراد بسیاری در توسعه این افزونه مشارکت داشته‌اند. پارسی‌دیت در تمام این مدت به صورت رایگان و متن‌باز
توسعه داده شده و در اختیار کاربران بوده و توسط تیم وردپرس پارسی پشتیبانی شده است. این افزونه به صورت منظم آپدیت می‌شود و
همواره نیازهای کاربران وردپرس فارسی را تحت پوشش قرار می‌دهد.

## Description

WP Parsidate is a feature-rich WordPress plugin designed by Persian developers to enhance the experience of
Persian-speaking users. It seamlessly integrates the Shamsi (Jalali) calendar throughout WordPress while providing
character and number localization, RTL optimization, and compatibility with popular plugins. A comprehensive WordPress
plugin that integrates the Solar Hijri (Persian/Shamsi/Jalali) calendar into your WordPress site with full RTL support.

## ✨ Key Features

### Date & Calendar Functionality

- 🗓️ **Shamsi (Jalali) Calendar** - Complete Solar Hijri calendar support
- 📅 **Date Conversion** - Automatic conversion throughout WordPress
- 📍 **Archive Widgets** - Shamsi date-based post archives
- 📆 **Calendar Widget** - Interactive Persian calendar widget
- 🔗 **Permalink Support** - Shamsi dates in custom permalinks

### Editor & Admin Integration

- ✏️ **Gutenberg Support** - Shamsi date picker in Block Editor
- 🎨 **ACF Integration** - Persian date field type for Advanced Custom Fields
- ⚙️ **Admin Dates** - Shamsi dates throughout WordPress admin dashboard
- 📝 **Content Dates** - Automatic Persian dates in posts, pages, comments, and archives

### Commerce & E-commerce

- 🛒 **WooCommerce Ready** - Full WooCommerce compatibility with Persian dates
- 📦 **Product Support** - Persian dates for orders, products, and customer data

### Text & Character Processing

- 🔤 **Arabic to Persian** - Automatic character conversion (ي/ك to ی/ک)
- 🔢 **Number Localization** - Convert Eastern Arabic and Latin numerals
- 📖 **Full RTL Support** - Complete right-to-left text direction optimization
- ✏️ **TinyMCE Adjustments** - RTL-optimized WordPress editor

### Performance

- ⚡ **Lightweight** - Minimal resource usage and fast performance
- 🎯 **Efficient** - Optimized code for production environments
- 📡 **WP-Planet Widget** - Integration with [WP-Planet.ir](https://wp-planet.ir)

## Development

### Running the tests

The test suite runs on top of the official WordPress test library, so tests use real WordPress functions instead of mocks.

```bash
# 1. Install PHP dependencies (includes PHPUnit and the PHPUnit Polyfills)
composer install

# 2. Install the WordPress test library (once). Needs MySQL/MariaDB and svn.
bash bin/install-wp-tests.sh wordpress_tests root '' localhost latest

# 3. Make sure MySQL/MariaDB is running, then run the tests
composer test
```

`composer test` runs `bin/phpunit.php`, which defines `ABSPATH` before PHPUnit boots. The plugin's Composer autoloader loads `inc/Functions/*.php`, and those files stop execution when `ABSPATH` is missing, so invoking `vendor/bin/phpunit` directly exits silently.

#### Windows (MAMP/XAMPP)

`bin/install-wp-tests.sh` requires Bash, Subversion, and `curl`/`wget`. If those are unavailable, install the test library manually:

1. Check out the `tests/phpunit` directory of `WordPress/wordpress-develop` for the WordPress version you are running. For example, for WordPress 7.1.4:
   ```bash
   git clone --depth 1 --branch 7.1.4 --filter=blob:none --sparse https://github.com/WordPress/wordpress-develop.git
   cd wordpress-develop
   git sparse-checkout set tests/phpunit
   ```
2. Copy `tests/phpunit` to `%TEMP%\wordpress-tests-lib`.
3. Create `%TEMP%\wordpress-tests-lib\wp-tests-config.php` from `wp-tests-config-sample.php`. Set `ABSPATH` to your WordPress root, point `DB_NAME` at a **separate empty database** such as `wordpress_tests`, and fill in your database credentials.
4. Make sure MySQL is running, create the test database, then run `composer test`.

The bootstrap uses `WP_TESTS_DIR` when set, otherwise `%TEMP%\wordpress-tests-lib` (`sys_get_temp_dir()`).

Tests live in `tests/unit` and cover the core plugin and every addon in `inc/App/Integration`. Every pull request runs them automatically on PHP 7.4 to 8.4 via GitHub Actions (`.github/workflows/testing.yml`).

JavaScript tests (Bookly adapters, the Jalali engine, the shared datepicker) need Node 21+ for the test runner's glob support: `npm install` once, then `npm run test:js`.

One of those tests rebuilds `assets/js-admin` from `assets/js-admin-src` with webpack and fails when the committed bundles differ, so a source edit must be followed by `npx webpack --no-watch` and a commit of the rebuilt files.

### Releasing

Nothing is published automatically; the release ZIP is built and uploaded by hand.

1. Set `Version:` in `wp-parsidate.php` and `Stable tag:` in `readme.txt` to the new version.
2. Add the `= x.y.z =` changelog entry to `readme.txt` — `ReleaseTest` fails without it.
3. Run the suites: `composer test` and `npm run test:js`.
4. Tag and push (`git tag 6.6 && git push origin 6.6`); the tag reruns both suites in GitHub Actions as a final check.
5. Remove the development packages before building the ZIP: `composer release`. The committed `vendor/` holds PHPUnit and its dependencies, and its autoloader loads PHPUnit files on every request. Never leave them out with `.distignore` instead: the autoloader would still require them and every site would get a fatal error.
6. Check the result: `vendor/phpunit` must not exist and `vendor/composer/autoload_files.php` must not mention `phpunit` or `yoast`.
7. Build the ZIP / copy to SVN, then restore the development packages with `composer install`.

Files listed in `.distignore` are left out of the ZIP.
